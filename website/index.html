TetherIA Aero Hand Open

An Isaac Lab port of the Aero Hand for a grasp-and-hold task — close around an object, hold it against gravity, don't drop it.

Overview

The hand mounts pointing straight down, closes around an object, and has to keep holding it against gravity for the whole episode. Four objects share one codebase — mug, bottle, card, and pen — each with its own tuned config and environment file, but the same hand model, action space, and reward structure underneath.

The action space, observations, and rewards follow the conventions from TetherIA's own official environment (a cube-rotation task in mujoco_playground): tendon-space control and torque/energy-aware rewards, reused here even though TetherIA hasn't published a grasp task of their own.

A separate real_hand/ directory drives the physical hand over ROS2, using the exact same 7-number action convention as the simulated policy, so a trained policy can move to hardware without a translation layer in between.

Architecture

Most of the codebase is shared across all four objects — only a handful of files and values actually change per object.

Shared by every object

  • Hand asset & actuator gains
  • 7-tendon action mapping
  • 68-dim observation layout
  • Reward structure (which terms exist)
  • Orientation-tuning workflow

Tuned per object

  • Object config — USD, mass, spawn offset
  • Tuned grasp pose
  • Drop-height threshold
  • Two reward scale values
  • Torque / energy / pose reward tuning

File layout

aero_hand_cfg.py

Hand asset, actuator gains, and base orientation — identical for every object.

aero_hand_scene_cfg.py

Thin scene wrapper: ground plane, light, N cloned hands. Not object-specific.

<object>_cfg.py

One per object — USD path, mass, and spawn offset relative to the hand.

<object>_grasp_env.py

The actual DirectRLEnv: actions, observations, rewards, resets. Same shape in every variant, with the object's name swapped in.

test.py

Loads a variant's tuned grasp pose across N envs to eyeball the grip — no RL loop. (Named test_sim.py in mug/ to avoid clashing with real_hand/test_ros.py.)

run_aero_hand_parallel.py

Bare hand-only scene check — no object, no RL, just cloned hands curling open and closed.

Hardware files — real_hand/

Everything that talks to the physical hand lives here and nowhere else — it's object-agnostic, so it sits at the top level instead of being copied into each variant.

real_hand/aero_hand_bridge.py

Talks to the real hand over ROS2 in the same 7-actuator convention as the sim. Also reconstructs joint angles from motor feedback, since the hardware has no joint encoders. Its coupling constants have to match every <object>_grasp_env.py.

real_hand/test_ros.py

A scripted demo — finger wave, counting, thumb opposition — that doubles as an end-to-end hardware check.

Variant scripts import the bridge from their own directory like this:

import pathlib, sys
sys.path.insert(0, str(pathlib.Path(__file__).resolve().parent.parent / "real_hand"))
from aero_hand_bridge import AeroHandBridge

Before you train

A few values are still placeholders and worth checking first: _DOWNWARD_FACING_EULER_DEG, stiffness, and effort_limit_sim in aero_hand_cfg.py (shared); object mass and spawn pos in each <object>_cfg.py; and rew_scale_torques / rew_scale_energy in each <object>_grasp_env.py, which need verifying against real torque magnitudes once you can log them.

The 7-tendon action space

The real hand has 7 motors driving 16 joints through tendons, so it's under-actuated by design — many joints are mechanically forced to move together. The policy outputs 7 normalized values, one per actuator, and each is broadcast to every joint it physically drives:

right_thumb_cmc_abd_actthumb base abduction
right_thumb_cmc_flex_actthumb base flexion
right_thumb_tendon_actthumb mcp + ip
right_index_tendon_actindex mcp + pip + dip
right_middle_tendon_actmiddle mcp + pip + dip
right_ring_tendon_actring mcp + pip + dip
right_pinky_tendon_actpinky mcp + pip + dip

This mirrors TetherIA's own "compact representation" from their SDK docs, reimplemented in Isaac Lab as a broadcast matrix, since PhysX doesn't model MuJoCo-style tendons directly.

Independent vs. forced-equal joints

Only the two thumb-base joints move independently. The rest fall into five 3-joint clusters — thumb tip, index, middle, ring, pinky — where every joint in a cluster is forced to the same commanded angle. The grouping is fixed by the hand's mechanics and identical across objects; only the angles being averaged change with each object's tuned grasp pose. Pinch grasps (card, pen) tend to want a bigger gap between mcp and pip/dip than power grasps (mug, bottle), since a pinch relies more on independent fingertip placement — exactly the precision this coupling gives up.

Caveat. This matches TetherIA's documented compact representation, but the real hardware's thumb coupling is actually more complex — moving one thumb actuator physically tugs on the others, nonlinearly. That deeper coupling isn't reproduced here, and Isaac Lab doesn't simulate real tendons either, so this is an approximation of an approximation — good enough to train a policy that speaks the same 7-number language as the real hand, not a physically exact model of the cables.

The reset pose (grasp_joint_pos) still sets all 16 joints directly at the start of each episode — only the ongoing control during the episode goes through the 7-number action space.

Rewards

Named after TetherIA's own reward terms, adapted from "rotate as fast as possible" to "hold still without dropping." The structure is shared across objects; two scale names embed the object's name and get tuned per variant.

Held rew_scale_<object>_height

Reward each step the object hasn't dropped past the threshold.

Stillness rew_scale_<object>_still

Penalizes object movement, for a steady, non-wobbly grasp.

Action rate

Penalizes jerky tendon commands between steps.

Pose

Pulls the 16-joint hand shape back toward its tuned grasp pose.

Torques & energy

Penalize actuator effort and wasted mechanical power. Placeholder scales — tune per object.

Drop penalty

Flat penalty applied every step the object counts as dropped.

Each object defines its own drop-height threshold — how far it can sink from its reset height before it counts as dropped — since a few centimeters means something very different for a pen than a bottle.

Hand orientation

The hand's downward-facing base rotation lives in aero_hand_cfg.py as an Euler angle rather than a raw quaternion, so it's easy to nudge by eye — the same workflow used for tuning a grasp pose or an object's spawn offset.

Object variants

Each of the four variants — mug, bottle, card, pen — customizes the same few things:

  • Its own object config: USD path, mass, spawn offset.
  • A tuned grasp pose, eyeballed with test.py.
  • A spawn offset that places the object inside the closed grip for its own geometry.
  • A drop-height threshold sized to the object.
  • Reward scale tuning — pinch grasps (card, pen) want different regularization than power grasps (mug, bottle).

Running the simulation

Sanity-checking the scene

./isaaclab.sh -p run_aero_hand_parallel.py --num_envs 100

No object, no grasp env, no RL — just N cloned hands driven by one shared curl, with a random reset every 300 steps. It confirms cloning, joint control, and reset plumbing before layering an object or the grasp env on top. Good first thing to run in a new setup.

Photo slots below — drop in screenshots of the parallel simulation setup in Isaac Lab.

Checking a tuned grasp pose

# visually check the tuned grasp pose across N envs, no RL loop
python test.py --num_envs 100

# fewer envs for faster iteration while tuning
python test.py --num_envs 9

Point test.py at whichever variant you want to check. Unlike the parallel sanity check, this goes through the real AeroHandGraspEnv — object included, actions passed through the actual tendon mapping — so you can eyeball whether the grip actually holds.

Training

Every variant behaves like any other Isaac Lab DirectRLEnv — 7 actions, 68 observations — so it drops into whatever PPO setup you're already using, just with a smaller action space than the original 16-joint version.

Running on the real hand

The bridge speaks the same 7-actuator, radians convention the sim policy outputs, so nothing needs converting between the two.

One-time setup

Requires ROS2 Humble, the aero-hand-open workspace, and the aero_open_sdk Python package.

The SDK needs a small patch to talk to the hand over USB: the hand's chip holds itself in reset until it sees DTR and RTS explicitly released, which pyserial doesn't do by default — without the fix, every command dies with ACK (opcode 0x31) not received. Add a wake sequence to AeroHand.__init__ before its first command:

self.ser.dtr, self.ser.rts = True, True
time.sleep(0.3)
self.ser.dtr, self.ser.rts = False, False   # release EN, chip boots
time.sleep(0.3)
self.ser.dtr, self.ser.rts = True, False    # run mode
time.sleep(1.0)                             # let it boot before talking

The SDK also installs as a non-editable copy by default, so patch it via an editable install:

pip install -e /path/to/aero-hand-open/sdk

Starting the hardware node

ros2 run aero_hand_open aero_hand_node --ros-args \
    -p right_port:=auto -p control_space:=joint

Use right_port:=auto — the wake sequence causes the device to re-enumerate, so the port number moves around. Only run one node at a time; a second instance resets the chip out from under the first.

Network isolation

A FastDDS profile pointed at another machine will silently let you see, and command, that machine's hand instead of your own. Force local-only discovery:

unset FASTRTPS_DEFAULT_PROFILES_FILE
export ROS_LOCALHOST_ONLY=1
ros2 daemon stop        # the daemon caches discovery config

Shell startup files only apply to newly opened terminals, so a stale terminal is the usual culprit if this stops working after being "fixed."

The bridge API

with AeroHandBridge() as hand:
    hand.send_actuator_positions([0.0, 0.3, 0.35, 0.6, 0.6, 0.6, 0.6])
    hand.spin_once(timeout_sec=0.0)

    actuators = hand.get_actuator_feedback()   # 7,  radians, same space as the command
    joints    = hand.get_joint_feedback()      # 16, radians, JOINT_NAMES order
    motors    = hand.get_motor_feedback()      # 7,  radians, raw hardware
    currents  = hand.get_actuator_current_feedback()   # 7, mA, torque proxy

Travel limits, clamped silently by send_actuator_positions:

Thumb abduction≤ 1.745 rad
Thumb flexion≤ 0.956 rad
Thumb tip≤ 2.618 rad
Index / middle / ring / pinky≤ 1.571 rad

The hardware has no joint encoders — it only reports 7 motor angles. get_joint_feedback() reconstructs the 16 joint angles by inverting the tendon model; it's accurate but blind to tendon stretch or a finger physically blocked by the object. For real contact sensing, use get_actuator_current_feedback() (motor current).

Motor-space and actuator-space readings aren't the same number — compare against what you sent using get_actuator_feedback(), not get_motor_feedback(), which is the raw gear-reduced value. Expect a percent or two of tracking error on the fingers and a bit more on the thumb — ordinary servo and tendon compliance, not a units bug.

Control rates

Hand sensing100 Hz
Hand commandsevent-driven, unthrottled
Sim policy60 Hz

Align the 60 Hz sim with the 100 Hz hand before pushing a policy to hardware — e.g. decimation = 1 for 120 Hz, or drop feedback_frequency to 60. Commanding a 100 Hz hand at 60 Hz is otherwise fine, since commands latch until the next one arrives.

Demo

python3 real_hand/test_ros.py

About 25 seconds of finger wave, counting, thumb opposition, and a slow clench, streamed at 100 Hz with smoothstep easing. Ctrl+C glides back to an open palm instead of freezing mid-pose. The pinch poses are geometric estimates, not measured — nudge them if a pinch misses on your unit.

Troubleshooting

ACK (opcode 0x31) not received

Missing DTR/RTS wake sequence, or the SDK patch isn't actually live (non-editable install).

No feedback from hand, or topics listed but no data

A stale terminal still has the FastDDS unicast profile set — open a new shell and run ros2 daemon stop.

Node starts, then reads fail

Two nodes running — the second reset the chip, which re-enumerated to a new device path.

Feedback looks ~2.5× too big

Reading get_motor_feedback() where get_actuator_feedback() was meant.
